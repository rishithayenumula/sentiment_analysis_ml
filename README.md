# Sentiment Bureau — Sentiment Analysis on Text Data

## Overview
A beginner-friendly sentiment analysis project using classical machine learning
(TF-IDF + Logistic Regression / Naive Bayes). What started as a notebook-only
exercise now also ships as a small Flask web app with a "case file" styled
frontend, so you can actually type a sentence and get a live prediction
instead of only reading notebook output.

This is still a **learning project**: the model is trained on a small,
labelled dataset and is meant to demonstrate the end-to-end ML + web
workflow, not to serve as a production-grade sentiment engine.

## What changed from the original version
- **Dataset grew from 6 rows to 90**, balanced across positive/negative, so
  evaluation numbers mean something (a 6-row split can't produce a
  trustworthy accuracy figure).
- **5-fold cross-validation** added alongside the train/test split, since
  a single split on a small dataset can be misleading either way.
- **Bigrams added** to `TfidfVectorizer` (`ngram_range=(1, 2)`) to catch short
  phrases like "not worth" that unigrams alone would miss.
- **The trained model + vectorizer are now saved** (`model/model.pkl`,
  `model/vectorizer.pkl`) via `joblib`, so you don't have to retrain every
  time you want a prediction.
- **A Flask API + frontend** were added on top of the model so it's usable
  as an actual tool, not just notebook cells.
- `requirements.txt` now includes `flask`, `joblib`, and `gunicorn` (for
  deployment).

## How to Run Locally

1. Clone the repository and enter the folder:
   ```bash
   git clone https://github.com/rishithayenumula/sentiment_analysis_ml.git
   cd sentiment_analysis_ml
   ```

2. Create a virtual environment (recommended) and install dependencies:
   ```bash
   python -m venv venv
   source venv/bin/activate   # Windows: venv\Scripts\activate
   pip install -r requirements.txt
   ```

3. Train the model (this creates `model/model.pkl` and `model/vectorizer.pkl`):
   ```bash
   python train_model.py
   ```

4. Run the web app:
   ```bash
   python app.py
   ```
   Then open **http://localhost:5000** in your browser.

   (You can still open `sentiment_analysis.ipynb` in Jupyter if you just
   want to explore the modeling side, exactly as before.)

## API

`POST /api/predict`
```json
// request
{ "text": "The staff were incredibly rude to us" }

// response
{
  "sentiment": "negative",
  "confidence": 0.62,
  "breakdown": { "positive": 0.38, "negative": 0.62 }
}
```

`GET /api/health` — simple liveness check, returns `{"status": "ok"}`.

## Deploying it

The app is a single Flask service (frontend + API together), which makes
deployment simple — one service, no separate frontend host needed.

### Option A: Render (recommended, free tier available)
1. Push this project to a GitHub repository (commit `model/model.pkl` and
   `model/vectorizer.pkl` too, so Render doesn't need to retrain on deploy).
2. Go to [render.com](https://render.com) → **New** → **Web Service** →
   connect your GitHub repo.
3. Configure:
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `gunicorn app:app`
   - **Environment:** Python 3
4. Click **Create Web Service**. Render will build and give you a public
   URL (e.g. `https://sentiment-bureau.onrender.com`).

### Option B: Railway
1. Push to GitHub, then go to [railway.app](https://railway.app) → **New
   Project** → **Deploy from GitHub repo**.
2. Railway auto-detects Python. Set the start command to `gunicorn app:app`
   if it's not picked up automatically (Settings → Deploy).
3. Deploy — Railway gives you a public URL automatically.

### Option C: Any VPS (e.g. a plain Ubuntu server)
```bash
git clone <your-repo-url>
cd sentiment_analysis_ml
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python train_model.py
gunicorn --bind 0.0.0.0:8000 app:app
```
Then put nginx (or Caddy) in front of port 8000 for TLS/HTTPS.

### Notes for any option
- `PORT` is read from the environment (`app.py` falls back to 5000 locally);
  Render/Railway set this automatically.
- If you don't commit `model/*.pkl`, add a one-off build step that runs
  `python train_model.py` before `gunicorn app:app` starts, otherwise the
  app will fail to find the model files.

## Models Implemented
- Logistic Regression
- Multinomial Naive Bayes

`train_model.py` cross-validates both and automatically saves whichever
scores higher.

## Results
With the expanded 90-row dataset, both models land around **70% cross-validated
accuracy** — reasonable for a small classical bag-of-words model, and honest
given the dataset size. Predictions on sentences that use very different
vocabulary from the training set will be less reliable; this is expected
behavior for TF-IDF-based models trained on limited data, not a bug.

## Learning Outcomes
- Text preprocessing and feature extraction
- Supervised machine learning concepts, including why dataset size affects
  how much you can trust an evaluation metric
- Model evaluation and comparison (cross-validation vs. single split)
- End-to-end ML workflow: notebook → saved model → API → frontend → deployment
